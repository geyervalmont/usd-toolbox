# Geometry LOD sets

`generate_scene_lods` generates alternative geometry levels from one immutable
neutral scene. Every level starts from the same original geometry, so its error
budget does not accumulate through preceding levels. This is a standalone
creation API; it does not edit an existing `SceneDocument` or advance its revision.

```rust
use usd_toolbox_core::scene::*;
fn generate(source: &Scene) -> Result<(), SceneError> {
let options = SceneLodOptions {
    levels: vec![
        SceneLodRequest {
            name: "medium".into(),
            face_ratio: 0.5,
            max_vertex_displacement: 0.01,
        },
        SceneLodRequest {
            name: "low".into(),
            face_ratio: 0.25,
            max_vertex_displacement: 0.02,
        },
    ],
    ..Default::default()
};
let levels = generate_scene_lods(source, &options, &SceneLimits::default())?;
let manifest = levels.manifest(); // usd-toolbox.geometry-lods.v1
assert_eq!(manifest.levels.len(), 2);
for result in levels.into_scenes() {
    let (report, scene) = result?;
    // Export this scene, then drop it before requesting the next one.
    println!("{}: reached={}", report.name, report.target_reached);
    drop(scene);
}
    Ok(())
}
```

A face ratio is in `(0, 1]` and targets the original mesh's triangulated face count,
rounded down with a minimum of one triangle. Ratios and displacement limits are
explicit; no unit-dependent error budget is guessed. Displacement is measured in
source scene coordinates. Multiply by `meters_per_unit` to express it in metres.
Level names are unique, case-sensitive ASCII alphanumeric/underscore/hyphen strings
of 1–64 bytes. Request order determines output order; changing order does not
change any level's geometry.

Each level retains scene, node and mesh IDs, source paths, materials, metadata,
transforms and shared placements. Per-face material subsets are remapped for every
placement. Material boundaries across any placement and corner-attribute seams
constrain collapse. Open boundaries remain locked. Tangents are cleared and must
be regenerated by an exporter when needed. Level names appear in reports and
provenance; the source object's display names and identities are retained.

`SceneLodManifest` records a SHA-256 of complete neutral source content, an optional
original-file hash, units, requests, achieved face/vertex counts, displacement and
target status. The neutral hash is streamed without allocating a full serialized
scene buffer. Source hashes and level provenance distinguish derivatives even
when they intentionally share stable identities.

The conservative edge-collapse algorithm checks manifold links, local winding and
duplicate triangles. Its bound is **maximum original-vertex displacement**. It
does not promise a Hausdorff/surface-error bound, UV-distortion limit, equivalent
shading or absence of global intersections. A level can remain above its requested
face count because topology, seams, error constraints or bounded work prevent more
collapses. Inspect each mesh's `target_reached` and geometry notes. Smaller ratios
do not guarantee proportionally smaller files. This API creates alternative scenes;
format-specific LOD extensions or runtime distance selection belong to consumers.

Defaults allow eight levels, 256 MiB estimated retained derivative bytes, five
million aggregate triangulated faces and fifteen million aggregate source corners.
Preflight reserves the uncollapsed triangulated upper bound: targets may be
unreachable, so the requested ratios cannot safely reduce that reservation. Per-mesh
collapse loop work is capped at 64 times its source corner count; all requested
levels are charged independently. Scene validation, triangulation and scratch
limits also apply. These are bounded work/storage categories, not exact RSS limits.
Raise budgets explicitly for measured workloads.

Generation owns derivative meshes and remapped subsets while borrowing source
hierarchy, metadata, materials and images. `into_scenes()` moves each level's mesh
buffers into an owned scene and copies the common data only at that explicit step.
There is no whole-scene clone merely to assign a level name. Sequentially export
and release scenes to avoid retaining multiple copies of large textures.

`SceneLodSet::export_with` accepts a Rust exporter callback, returns
`SceneLodExports { manifest, levels }`, and rejects aggregate encoded outputs above
`max_output_bytes`. Each entry contains its level report and `SceneExport` bytes
and diagnostics. It drops prepared results on failure and does no publication.
The callback must enforce its own per-export output and scratch budgets: an
aggregate check after encoding cannot prevent that encoder's allocation. Geometry
and encoded-output budgets are accounted separately, so their combination and the
borrowed source can occupy more memory than either individual budget.

The CLI packages these derivatives into a new directory:

```sh
usd-toolbox model lod --input chair.usdz --options lod.json \
  --output-dir chair-lods --target glb
```

`lod.json` is a `SceneLodOptions` object with a `levels` array as above. Targets are
`glb` or `usdz`. `manifest.json` retains the core manifest fields and adds target,
import diagnostics and file names, SHA-256 hashes, byte lengths and export losses.
Files are deterministically named `lod-0.glb`, `lod-1.glb`, and so on; the original
requested names remain in the manifest. Existing destination paths, including
empty directories and symlinks, are refused. Completed files are staged beside the
destination before publication. On Unix, an empty destination is briefly reserved
before the completed directory atomically replaces that owned reservation.

The C document request is `{"operation":"export_lods","target":"glb","options":...}`.
It returns one prepared ZIP containing the same manifest and binary level files;
the separate report buffer contains the exact manifest JSON. Sizing or copying
this result does not repeat generation or export, and the result outlives the
source document handle. ZIP headers and the separately retained report are included
in the output byte budget; a conservative header reservation may reject a nearly
full budget before encoding the archive. Rust callers can use the standalone API
for separate output files without ZIP packaging.

Native wrappers cap requests at eight levels and configured scene budgets, with
at most 512 MiB encoded output. Explicit smaller budgets still apply. None of these
operations changes the source document or its query generation.

The browser worker returns transferred binary files alongside the same manifest:

```js
const lods = await model.exportLods({
  levels: [{ name: 'medium', face_ratio: 0.5, max_vertex_displacement: 0.01 }],
}, 'glb', { textureTier: 'preview' });
// lods.manifest.files records byte lengths, SHA-256 hashes and export diagnostics.
// lods.files contains { name, bytes: Uint8Array } entries owned by the caller.
```

Browser requests use fixed browser scene limits and allow at most eight levels
and 128 MiB aggregate encoded output, with separate geometry/source-work caps.
Explicit smaller budgets apply. Both `glb` and `usdz` are supported; texture tier
and vertex-cache options apply only to GLB. Cancellation follows the worker's
documented request/termination policy. Texture downsampling and geometry reduction
remain independent decisions.
